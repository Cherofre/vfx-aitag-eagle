# Product

## Register

product

## Users

Game VFX artists, technical artists, and asset-library maintainers who use Eagle to collect, inspect, tag, and retrieve visual-effect references. They work inside Eagle while browsing media, batching selections, reviewing AI suggestions, and writing controlled tags back to assets.

## Product Purpose

This plugin turns selected Eagle assets into a controlled AI tagging workflow for VFX images, GIFs, videos, and previewable design files. Success means users can collect materials without losing context, run local Claude/Codex or Eagle AI analysis, review suggested tags quickly, see what is missing from the current tag pool, preview media without interrupting playback, and write only the tags they accept.

## Brand Personality

Practical, focused, and craft-aware. The interface should feel like a compact production tool: calm enough for repeated work, precise enough for tag review, and visually aligned with Eagle's dark plugin environment.

## Anti-references

Avoid landing-page composition, decorative panels, oversized copy, author/QQ promotional text, whole-page scrolling, bulky result rows, and UI that shifts when filenames or tag labels are long. Avoid hiding primary analysis progress or making users hunt for result meaning.

## Design Principles

- Keep the main workbench single-screen: whole-page scroll is a bug; only local regions scroll.
- Make review actions stable: controls must not move when filenames, paths, or tag labels are long.
- Separate true library state from temporary candidates: Eagle tags, default-template gap tags, and manual tags need clear but compact source signals.
- Prefer dense, familiar controls over decorative explanation.
- Protect user intent: analysis may suggest, but writing tags should remain explicit unless the user enables an automatic path.

## Accessibility & Inclusion

Use readable contrast on the dark UI, visible focus states, stable hit targets, and text truncation that preserves full values through titles/tooltips. Motion should be short and state-driven; reduced-motion behavior should not hide content.
